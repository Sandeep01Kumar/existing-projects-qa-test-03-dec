# Repository assets

Six files in this repository have nothing to do with the HTTP service. They are
deliberate fixtures, not abandoned clutter, and this page owns their
**provenance** for the whole documentation corpus.

Source files this page derives from: `LoginTest.java`, `industry.csv`,
`test.txt.txt`, `sample.doc`, `demo.jpg`, `100Pages.pdf`.

## Why a Node.js repository contains a Java file and a PDF

This repository is a test fixture for tooling rather than a product. Tooling that
walks a repository has to cope with more than one language and more than one file
format — text and binary, tiny and large, valid and deliberately invalid — and
the fastest way to exercise that is to keep a small spread of real files
committed. The six below are that spread.

The important consequence is a preservation policy: **none of these files may be
deleted, repaired, or reformatted.** Each one's oddity is the fixture. Deleting
the empty file or fixing the Java file removes exactly the property that made it
worth committing.

## LoginTest.java

Declares package `com.blitzyTest` and a `public class LoginTest` with a
`public static void main(String[] args)` method. The method body is the bare,
unresolved identifier `Web` at `LoginTest.java:L7`.

**It will not compile, and that is intentional.** `Web` refers to nothing: there
is no import that would define it, no class by that name in the repository, and
no build configuration that would resolve it. It is not a bug awaiting a fix, and
it is not evidence of a truncated commit.

Three practical notes follow:

- Nothing in this repository compiles it. There is no `pom.xml`, no
  `build.gradle`, no `javac` invocation, and no CI step that touches Java.
- JSDoc does not apply to it. The documentation toolchain reads only `server.js`,
  as configured in `jsdoc.json`.
- Do not "fix" it. A compilable version would no longer be a fixture for
  non-compilable input.

## industry.csv

44 lines: one header row containing the single column name `Industry`, followed
by 43 rows of industry category labels. The first three lines are:

```text
Industry
Accounting/Finance
Advertising/Public Relations
```

Two properties matter if you ever consume it. The values are **labels, not
identifiers** — there is no numeric ID, no stable key, and no guarantee of
ordering, so joining on them means joining on display text. And some labels
contain a `/`, as both examples above show, which trips naive splitting on
anything other than the comma delimiter.

Nothing in the service reads this file. It is data-shaped input for tooling that
wants some.

## test.txt.txt

**Zero bytes, on purpose.** The emptiness is the fixture: it exercises the
zero-length path in anything that reads files, and the doubled `.txt.txt`
extension exercises naive extension parsing at the same time.

Do not prune it. An empty file looks exactly like an accident, which is precisely
why it is documented here rather than left to be discovered and cleaned up.

## sample.doc, demo.jpg and 100Pages.pdf

Three binary fixtures spanning three formats and three orders of magnitude:

| File | Size | Exercises |
| --- | --- | --- |
| `sample.doc` | 98 KB | Legacy Word binary format, which is neither text nor a modern zipped container |
| `demo.jpg` | 2.1 MB | Image handling, and a payload large enough to make streaming versus buffering matter |
| `100Pages.pdf` | 9.5 MB | Multi-page document handling, and the largest single file in the repository |

None is read by the service, and none is generated by any command here. They are
committed inputs, which is why cloning this repository transfers roughly 12 MB
even though the application is 14 lines long.

## Preservation policy

| Action | Allowed? |
| --- | --- |
| Read them | Yes |
| Copy them for a test | Yes |
| Delete any of them | No |
| Repair `LoginTest.java` so it compiles | No |
| Add content to `test.txt.txt` | No |
| Reformat or re-encode `industry.csv` | No |
| Recompress or replace the binary fixtures | No |
| Add them to `.gitignore` | No — they are tracked deliberately, and verified not to be ignored |

If a tool in this repository trips over one of these files, the tool's
configuration is what changes. `jsdoc.json` restricts JSDoc to `server.js`,
`.markdownlint-cli2.jsonc` restricts linting to Markdown, and
`tools/check-links.js` walks only Markdown — three examples of scoping the tool
rather than pruning the fixture.
